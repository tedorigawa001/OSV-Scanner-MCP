# v0.9.0

## Direct and Transitive Dependencies for `pom.xml`

`scan_project` and `suggest_fix` now report `dependency_relation` for Maven packages from `pom.xml` (previously `unknown`).

osv-scanner reports a `pom.xml` as two separate results: the dependencies declared in the `pom.xml` and its parent POMs (`source.type: "lockfile"`), and the transitive dependencies resolved through deps.dev (`source.type: "unknown"`). The server uses this split instead of parsing the `pom.xml` itself, so the set of direct dependencies always matches osv-scanner's own interpretation of parent POMs, profiles, properties, and dependency management.

- Declared dependencies, including those inherited from a parent POM, those in profiles active by default, those whose group ID comes from a property, test-scoped and optional dependencies, are `direct`
- Dependencies resolved through deps.dev are `transitive`
- With `OSV_MCP_NO_REMOTE_RESOLUTION=1`, only declared dependencies are scanned, and all of them are `direct`
- A package that appears in both results of the same `pom.xml` is `direct`
- `introduced_by` and `declared_in` are not available for Maven, because osv-scanner does not report the dependency graph or where a dependency is declared
- This relies on undocumented osv-scanner output. Unexpected result types are reported as `unknown`, and the behavior will be re-checked whenever the pinned osv-scanner version changes
- `gradle.lockfile` packages remain `unknown`

`suggest_fix` now gives a Maven `update_hint`: for a direct dependency, update the `<dependency>` version, or the parent POM, property, or BOM that manages it; for a transitive dependency, override the version in `<dependencyManagement>` or update the direct dependency that requires it. No hint is given when the relation is `unknown`.

## Unchanged

- Recommended versions, notes, and per-vulnerability details are unchanged (verified against v0.8.0 on Maven, npm, Go, and PyPI projects).
- `scan_java_project`, `scan_java_artifact`, and `scan_sbom` responses are unchanged.

npm publication is separate from this GitHub release.
