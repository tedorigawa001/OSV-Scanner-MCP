# v0.3.0

## Added

- New `scan_sbom` MCP tool for CycloneDX 1.4/1.5/1.6 and SPDX 2.2/2.3 JSON files.
- SBOM source format, specification version and SHA-256 in scan reports.
- Coverage details distinguishing identified and unidentified packages. Inventory completeness and correspondence to build artifacts remain explicitly unverified.

## Input Handling

- Absolute local paths, allowed-root enforcement and regular-file checks.
- A 16 MiB input limit enforced while reading.
- Private scan snapshots with restricted permissions and cleanup on success or failure.
- Shared scanner concurrency, timeout and output limits.

## Validation

A separate Maven dummy project generated a CycloneDX 1.6 SBOM and a shaded fat JAR. All seven original dependency JAR hashes matched the SBOM, and 5,683 dependency classes matched the fat JAR byte-for-byte. SBOM and JAR MCP scans returned the same 17 package/version/vulnerability findings at verification time. Vulnerability totals may change with the OSV database.

Eight offline comparator tests covered matching input and rejection of missing, changed or extra classes, incorrect hashes, missing or changed metadata, and duplicate components.

This fixture has no application classes, relocation or minimization. Signatures, module descriptors and other resources were not compared. The fixture and comparator are separate from this repository and are not shipped in the npm package. The MCP server itself does not generate SBOMs or verify SBOM-to-artifact correspondence.

## Compatibility

Node.js >=20.19 is required. Existing tools remain available. XML, SPDX tag-value and SPDX 3 are not supported by `scan_sbom`. No npm publication is performed by the GitHub release.
