# v0.3.4

## Security Fix: Scans Could Read Files Outside the Scan Scope

Affected versions: v0.3.3 and earlier. Fixed in v0.3.4.

`scan_java_project` and `suggest_fix` passed the project directory to osv-scanner recursively (`-r`). osv-scanner then also read any `requirements.txt` in that directory and followed its include directives. A relative include such as `-r ../../outside/file.txt` caused a file outside the scanned directory to be read, even when `OSV_MCP_ALLOWED_ROOT` was set. Lines in that file that parse as `name==version` were added to the results and sent to `api.osv.dev` for vulnerability lookup. Absolute include paths were not followed.

Reaching this requires a `requirements.txt` placed inside a directory that is scanned, and only content that parses as pinned requirements is read into the results.

v0.3.4 no longer passes directories to osv-scanner. It passes only the detected `pom.xml`, `gradle.lockfile`, and `buildscript-gradle.lockfile` files, one at a time with an explicit format (`--lockfile <format>:<path>`).

## Other Fixes

- `suggest_fix` reported vulnerabilities of non-Maven packages (for example npm packages from a lockfile in the same directory) as having no fixed version (`unfixed`), even when a fix exists. Non-Maven packages now return `verification: "unsupported_ecosystem"` and `tier: "unsupported"`, and are not counted as unfixed.
- The `manifests` list in responses (searched to depth 3) could differ from what was actually scanned (unlimited depth). The detected manifests are now exactly the scan scope.
- Manifest discovery no longer stops at depth 3. Deeply nested `pom.xml` files are now listed and scanned. Discovery is bounded by 200,000 entries and 1,000 manifests; exceeding either returns the new error `manifest_search_limit_exceeded` instead of silently truncating (previously, discovery stopped at 100 manifests without notice).

## Behavior Changes

- `scan_java_project` and `suggest_fix` no longer scan non-Java lockfiles (such as `package-lock.json` or `requirements.txt`) that happen to be in the same directory. Multi-ecosystem scanning is planned for a separate tool in a later release.
- Specifying a manifest file directly (for example `/path/to/pom.xml`) now scans only that file. Previously the whole containing directory was scanned. This also lets you work around `manifest_search_limit_exceeded`.

npm publication is separate from this GitHub release.
