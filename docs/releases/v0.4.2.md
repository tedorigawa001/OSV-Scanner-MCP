# v0.4.2

## Bug Fix: `fixed_versions` Was Always Empty Outside Maven

Affected versions: v0.4.0 and v0.4.1 (`scan_project`), and v0.4.1 and earlier (`scan_sbom` for non-Maven components). Fixed in v0.4.2.

Fixed versions were collected only from Maven records, so every npm, Go, and PyPI package returned `fixed_versions: []`. Because an empty array was documented as "no fixed version exists", vulnerabilities that do have a fix (for example lodash 4.17.20, fixed in 4.17.21) could be read as unfixable.

`fixed_versions` now contains the fixed versions listed in OSV for every ecosystem:

- Maven: sorted by Maven version precedence (unchanged)
- npm and Go: sorted by Semantic Versioning 2.0.0 precedence. Go's `+incompatible` suffix is ignored for ordering, and Go pseudo-versions sort as pre-releases. Values that are not valid SemVer (such as `19.03.9` in some Docker advisories) are kept and placed at the end
- PyPI and other ecosystems: listed in the order given by OSV, without duplicates. The order is not guaranteed

Commit-based (`GIT`) ranges are not included, since commit hashes are not release versions. The list can include pre-release versions (`5.0.0-beta.3`) and Go pseudo-versions (`0.0.0-20180925071336-cf3bd585ca2a`). An empty array now means that OSV lists no fixed version.

## Bug Fix: Missing Parent POMs Were Not Reported

Affected versions: v0.4.1. Fixed in v0.4.2.

When a parent POM existed but could not be copied into the scan snapshot (larger than 10 MiB, a named pipe or other non-regular file, a symbolic link at the final path component), the child `pom.xml` was scanned without it and reported as fully scanned. Dependencies inherited from that parent were missing from the results, and `scan_project` could still report `coverage.complete: true`.

The child is still scanned, but the missing parent is now reported:

- `scan_java_project` / `suggest_fix`: new `incomplete_manifests` field with the reason, together with `scope_warning`
- `scan_project`: listed in `coverage.skipped_files` with the reason, and `coverage.complete` is `false`
- When the child itself declares no dependencies and the scan ends with `no_packages_found`, the error message includes the same reason

A parent POM that does not exist (for example the default `../pom.xml` of a root `pom.xml`) is not reported, because osv-scanner would not read it from the original location either.

## Other Fixes

- Copies into the scan snapshot could be truncated if the operating system wrote only part of a chunk. Each chunk is now written completely.
- Error details from osv-scanner (`detail`) contained paths inside the temporary snapshot directory. They now show the original file paths.

Fix recommendations (`suggest_fix`) remain Maven-only in this release. npm/Go support is planned for v0.5.0.

npm publication is separate from this GitHub release.
