# v0.5.0

## `suggest_fix` Now Supports npm and Go

`suggest_fix` recommends upgrade versions for npm and Go packages in addition to Maven. Python (PyPI) is not supported yet and is returned as `verification: "unsupported_ecosystem"` (planned for v0.6.0).

- **Version comparison**: npm and Go versions are compared by Semantic Versioning 2.0.0 precedence. Go's `+incompatible` suffix is ignored for ordering, and Go pseudo-versions sort as pre-releases.
- **Upgrade tiers**: for npm and Go, the "same series" follows npm's caret (`^`) compatibility. From 1.0.0 the tiers work as for Maven (`same_minor` / `major_internal` / `cross_major`). For 0.x, only updates within the same `0.minor` are `same_minor`, and a minor update (`0.3` → `0.4`) is `cross_major`. For 0.0.x, every update is `cross_major`. For example, golang.org/x/text 0.3.0 is recommended 0.39.0 as `cross_major`.
- **Affected-range verification**: OSV `SEMVER` and `ECOSYSTEM` ranges are checked for npm and Go, as `ECOSYSTEM` ranges already were for Maven. Ranges containing values that are not valid SemVer (such as `19.03.9` in some Docker advisories) are treated as incomplete, and the recommendation is withheld instead of guessed.
- **Pre-releases**: canary, beta, and pseudo-versions are recommended only when no stable candidate fixes every vulnerability, and are flagged with `recommended_is_prerelease: true`. A stable version in a higher tier is preferred over a pre-release in a lower tier.
- **`+incompatible`**: when the same Go version is listed with and without `+incompatible`, the form matching the current version is recommended, because a module path without `/vN` needs `+incompatible` for v2 and later.
- **Unparseable fixed versions**: a vulnerability whose fixed version cannot be parsed gets `tier: "unparseable_fix"`. It is not treated as unfixed, so the recommendation is withheld rather than verified against the other vulnerabilities only.
- **Unparseable current versions** (such as git or local-path dependencies) return `verification: "unparseable_version"` and are not counted as unfixed.
- **Update hints**: npm and Go suggestions include `update_hint`: for npm, update the direct dependency or use `overrides` in the root `package.json`; for Go, `go get <module>@<version>`, with a note that v2 and later majors use a different module path and are not included. A note is added when the current Go version is a pseudo-version.

Examples verified with osv-scanner and live OSV data: lodash 4.17.20 → 4.18.0 (`major_internal`), minimist 1.2.5 → 1.2.6 (`same_minor`), next 15.5.0 → 15.5.24 (a stable release, not a canary), express 4.17.1 → 4.20.0. Maven results are unchanged (log4j-core 2.14.1 → 2.25.4).

## Behavior Changes

- `suggest_fix` now detects and scans projects the same way as `scan_project`. In a Java project that also contains npm, Go, or Python lockfiles, those dependencies are included in the suggestions.
- `requirements.txt` files are now scanned by `suggest_fix` too. As with `scan_project`, the names and versions they declare are sent to deps.dev for transitive resolution unless `OSV_MCP_NO_REMOTE_RESOLUTION=1` is set.
- The `suggest_fix` response includes `coverage` (the same as `scan_project`) before the counts. `skipped_manifests` and `scope_warning` are replaced by `coverage.skipped_files` and `coverage.warning`.
- A Gradle project without `gradle.lockfile` now returns `no_manifest_found` with steps to generate the lockfile, instead of `gradle_lockfile_missing`, when passed to `suggest_fix`. `scan_java_project` is unchanged.
- In `scan_project` and `scan_java_project` responses, `affected_versions` for npm and Go vulnerabilities is now evaluated (`complete` can be `true`).

npm publication is separate from this GitHub release.
