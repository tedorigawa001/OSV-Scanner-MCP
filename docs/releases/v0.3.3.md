# v0.3.3

## Network Destinations and Privacy

Earlier README text stated that scans contact only the OSV database. That was inaccurate. Recording the outbound connections of osv-scanner v2.4.0 showed that scanning a `pom.xml` also contacts `api.deps.dev` (deps.dev, operated by Google) to resolve transitive dependencies. To resolve them, the names and versions of the dependencies declared in `pom.xml`, including internal package names, are sent to deps.dev. `gradle.lockfile`, JAR/WAR, and SBOM scans contact only `api.osv.dev`.

The README now has a "通信先とプライバシー" section listing each operation, the hosts it contacts, and what is sent.

## Changes

- New `OSV_MCP_NO_REMOTE_RESOLUTION=1` setting. It stops transitive dependency resolution through deps.dev for `pom.xml` scans. Only the deps.dev requests stop: package names and versions are still sent to `api.osv.dev` for vulnerability lookup under every setting. With this setting, vulnerabilities in transitive dependencies of `pom.xml` are not detected. The default behavior is unchanged.
- `scan_java_project` and `suggest_fix` responses include a new `dependency_resolution` field near the top. When resolution is disabled, it reports `transitive_resolution: "disabled"` with a warning, so a result with zero findings is not mistaken for a clean result.
- osv-scanner is always invoked with `--data-source deps.dev`. Its `native` data source connects to any repository URL listed in the scanned `pom.xml` (`<repositories>`), which would let a malicious `pom.xml` direct requests to an attacker-controlled host. This server never uses that mode, and a test enforces it.

No existing response fields were removed or changed.

npm publication is separate from this GitHub release.
