# v0.8.0

## `suggest_fix` Checks Recommended Versions Against OSV

Recommendations were verified only against the vulnerabilities found in the scan, which are the ones affecting the current version. A recommended version could therefore be affected by a vulnerability introduced after the current version. For example, cryptography 3.2 was recommended 49.0.0, which is affected by two vulnerabilities introduced in 44.0.0 and fixed in 50.0.0.

`suggest_fix` now queries `api.osv.dev` (`POST /v1/query`) for each recommended version. If the version is affected by vulnerabilities the scan did not see, those vulnerabilities are added to the set the recommendation must avoid, their fixed versions become candidates, and the recommendation is chosen again. In the example above, 50.0.0 is recommended and `upgrade_note` explains why 49.0.0 was skipped.

The result is reported in `candidate_check`:

- `clean`: OSV reports no known vulnerabilities for the recommended version
- `has_known_vulnerabilities`: no candidate avoids them (for example, a new vulnerability has no fix yet); the recommendation is kept and the IDs are listed in `recommended_known_vulnerabilities`
- `conflict`: OSV reports that a candidate is affected by a vulnerability the scan had already evaluated as not affecting it, and no other candidate is available; the recommendation is withheld (`recommended_upgrade: null`, `verification: "no_verified_candidate"`)
- `failed`: the query failed or returned a malformed response; the recommendation is still given, since it was verified against the scanned vulnerabilities
- `skipped`: the query limit was reached
- `disabled`: turned off with `OSV_MCP_NO_CANDIDATE_CHECK=1`

Only packages with a recommendation are queried. The request contains the package name (already sent to `api.osv.dev` during the scan) and the candidate version (a published fixed version). Limits: 4 queries per package, 60 per call, 4 at a time, 15 seconds and 4 MiB per response, and up to 5 result pages. A failed query never fails the tool call. Vulnerabilities found this way do not affect the current version, so they are not added to `per_cve_detail`.

Verified with live OSV data: cryptography 3.2 is now recommended 50.0.0; recommendations for the other test projects (Maven, npm, Go, and PyPI) are unchanged. In these tests, a whole `suggest_fix` call, including the scan and the queries, took 2 to 4 seconds.

## New Environment Variable

- `OSV_MCP_NO_CANDIDATE_CHECK`: set to `1` or `true` to skip the query. Recommendations are then the same as in v0.7.1, and `candidate_check` is `disabled`.

This release includes the v0.7.1 changes (cleanup of temporary directories when the server is terminated).

npm publication is separate from this GitHub release.
