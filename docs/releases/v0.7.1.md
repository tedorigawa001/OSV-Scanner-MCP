# v0.7.1

## Temporary Copies Are Removed When the Server Exits

Scans copy the target files into a private temporary directory (`osv-mcp-snap-*`, or `osv-mcp-sbom-*` for `scan_sbom`; accessible only by the owner) and delete it when the scan finishes. In v0.7.0 and earlier, if the server was stopped while a scan was running, the directory was left behind with copies of the project's files (for example `package-lock.json`, `go.mod`, and the generated `requirements.txt`), and the running osv-scanner process could outlive the server. MCP clients usually stop servers this way, by sending SIGTERM or closing stdin.

The server now cleans up before it exits:

- **SIGTERM, SIGINT, SIGHUP**: deletes the temporary directories, stops running osv-scanner processes, and exits with the conventional code (143, 130, 129).
- **stdin closed** (the client closed the transport): same cleanup, then exits with code 0. Running scans are not awaited, since there is no client to receive the result.
- **Other exits** (`process.exit`, uncaught exceptions): the same cleanup runs on exit.

A termination that cannot be caught (SIGKILL, the OOM killer, power loss) can still leave a directory behind. On startup, the server deletes leftovers from earlier runs, in the background so startup is not delayed. It deletes only directories that meet all of these conditions:

- the name is exactly `osv-mcp-snap-` or `osv-mcp-sbom-` followed by the 6 characters added by `mkdtemp`
- a real directory, not a symbolic link (symbolic links are never followed)
- owned by the current user
- last modified at least 24 hours ago, so directories in use by another server process are not touched

The startup cleanup is skipped on Windows, where the owner cannot be checked. Signal handling on Windows has not been tested.
