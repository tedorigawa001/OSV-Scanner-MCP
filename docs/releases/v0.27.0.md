# v0.27.0

## Security fix: repositories listed in scanned POMs are no longer contacted

Up to v0.26.0, scanning a `pom.xml` with dependency resolution enabled (the default) let OSV-Scanner fetch parent POMs and imported BOMs from every URL in `<repositories>`. This happened even though the server selects deps.dev. The URLs could be `http://` or loopback addresses. A crafted `pom.xml` could make the scanning machine send GET requests to an internal or attacker's server. Coordinates of internal parent POMs and BOMs were also sent to Maven Central. `scan_project`, `scan_java_project` and `suggest_fix` were affected. `OSV_MCP_NO_REMOTE_RESOLUTION=1` and offline mode were not.

- **Maven remote resolution is disabled**: the server no longer runs OSV-Scanner's Maven resolver. Scanning `pom.xml` contacts only `api.osv.dev`. Local parent POMs are still read from verified private copies
- **Repository declarations are removed**: `<repositories>` and `<pluginRepositories>` are removed from the private copies of `pom.xml` and its parent POMs, including those inside `<profiles>`. The original files are not changed. A parent reference to a copy that was not verified this way excludes the POM
- **Verified**: with OSV-Scanner 2.4.0, 2.7.0 and 2.7.1, and through the server with 2.7.0 and 2.7.1, for parent POMs, BOMs and repository declarations

`requirements.txt` is still resolved through deps.dev, and lockfiles are unaffected.

### Change in results

Transitive dependencies of `pom.xml` are no longer scanned by default. For example, Log4j API pulled in by Log4j Core is not reported unless it is declared. Dependencies that come only from remote parent POMs or imported BOMs are also missing.

- **Responses**: `dependency_resolution` has `maven_transitive_resolution: "disabled"` and a warning, as with `OSV_MCP_NO_REMOTE_RESOLUTION=1`. `transitive_resolution` is `"disabled"` unless `requirements.txt` entries are also resolved. `coverage.complete` is not lowered for this
- **Covering transitive dependencies**: use `gradle.lockfile` for Gradle builds. For Maven builds, scan a CycloneDX or SPDX SBOM with `scan_sbom`, or the built JAR/WAR with `scan_java_artifact`

Scanning, `suggest_fix` for other ecosystems, offline mode and the pinned OSV-Scanner 2.7.0 are unchanged from v0.26.0.

## Development

- Research validation records in `docs/validation` bind the exact `package.json` and `package-lock.json` bytes they were measured with. The version bump in this release makes them differ at HEAD again, as described for v0.23.0

## Verification

- Automated tests (product scope: 3,265 passed), type check and build, including regression tests for repository removal in each tool, profiles and prefixed elements, unverified parent copies, the resolver flag and mixed Maven and Python projects
- Dependency audit: `npm audit` and OSV-Scanner 2.7.0 on `package-lock.json` report no findings

npm publication is separate from this GitHub release.
