# v0.21.0

## Where dependencies come from: Bun, uv, Poetry, and PDM

`scan_project` and `suggest_fix` now report `dependency_relation`, `declared_in`, and `introduced_by` for four more lockfile formats, and `suggest_fix` uses them in its `update_hint`. For Python, the hint now names the declaring `pyproject.toml` or the direct dependencies that pull a package in.

- **Bun** (`bun.lock` text formats 0, 1 and 2): workspace `dependencies`, `devDependencies`, `optionalDependencies` and installed peers are direct, with the workspace's `package.json` in `declared_in`. Dependencies are resolved through the locked package placement, so nested versions, scoped names and npm aliases are told apart. Intentionally unresolved optional dependencies are not guessed from another installed package
- **uv** (`uv.lock` version 1, revisions 0–5): the normal, optional and development-group dependencies of workspace members are direct, with the member's `pyproject.toml` in `declared_in`. Optional dependencies of a package are followed only for the extras that were requested, and paths with different environment markers are not joined
- **Poetry** (`poetry.lock` lock versions 1.1, 2.0 and 2.1): the root `pyproject.toml` (project dependencies, optional dependencies, Poetry dependency, dev and group tables, and standard dependency groups) and confirmed child projects are direct. Unconditional dependencies are followed; dependencies with markers, extras or `optional` need an environment solver and stay unresolved
- **PDM** (`pdm.lock` lock versions 4.0–4.5.1): the root's groups selected by `metadata.groups` (project, optional, standard and `tool.pdm.dev-dependencies` groups, with `include-group`) and confirmed child projects are direct. Extras are separate identities, and PDM's editable declarations (`-e file:///${PROJECT_ROOT}/...#egg=name`) are matched by their explicit name and locked path
- **Nothing is guessed.** Names are compared with PEP 503 normalization and versions with PEP 440. Ambiguous names or versions, local, Git and URL sources, and packages that cannot be reached from a root are `unknown`. Bun, uv, Poetry, PDM, plugins and build backends are never run, and local paths are never followed to read source files. This is reachability over the locked packages, not a check that the lockfile is up to date

## Workspace and child coverage

A child manifest with no lockfile of its own, under a parent lockfile, was reported in `coverage.lockfile_missing` as `unconfirmed`. It is now checked against that lockfile:

- **Bun**: the child's directory must match a locked `workspaces` key exactly (after normalization)
- **uv**: the child must be a locked local package whose name is in `[manifest].members`
- **Poetry**: the child must be a locked `directory` package reachable from the root, with the same name and version, no development groups, no dynamic dependencies, and runtime declarations that agree with its locked dependency entries (including path dependencies on sibling children, such as `../core`)
- **PDM**: the child must be a locked `path` package that matches `[tool.pdm.workspace].members` or is reachable as a path dependency, with the same agreement checks as Poetry. Version constraints are compared regardless of order, and markers regardless of quote style and spacing; other differences are not solved

Only `pyproject.toml` children are checked for Python; `setup.py`, `setup.cfg` and `Pipfile` children stay `unconfirmed`. A confirmed child is no longer listed, so `coverage.complete` can now be `true` for these projects. A child that cannot be checked is still `unconfirmed`.

**Behavior changes:**

- In Bun, Poetry and PDM projects, a nested manifest that is absent from the parent lockfile (for example an example or test fixture) is now `missing` instead of `unconfirmed`
- In uv projects, a nested `pyproject.toml` that is absent from `uv.lock` is now `missing`. One that is locked but is not a workspace member (such as a path dependency) stays `unconfirmed`

## Limits and safety

- `bun.lock`, `uv.lock`, `poetry.lock` and `pdm.lock` are read once, within the selected scan directory, and the same captured bytes are used for coverage, relations and scanning. **Behavior change**: these lockfiles over 16 MiB (64 MiB in total per format), or that cannot be read safely, are now skipped with a reason in `skipped_files` (and `coverage.complete` is `false`) instead of being passed to OSV-Scanner directly. Companion `pyproject.toml` files are read up to 4 MiB each
- TOML is checked before parsing (nesting depth, dotted keys, and structure proportional to the file size), and duplicate keys and `__proto__` keys are rejected. Bun's JSONC is read with duplicate keys and deep nesting rejected
- **Larger lockfiles within the limits are now analyzed.** Each lockfile is parsed with its own budget sized from its length (1,024 operations per KiB, at least 2,000,000), instead of one budget shared by every lockfile of a format in the scan. Before, the budget ran out at a total of about 7.5 MiB for pnpm and Yarn and about 13.6 MiB for Bun, so later lockfiles in a directory with several projects lost their coverage and relations. The line limit for `pnpm-lock.yaml` and `yarn.lock` was raised from 200,000 to 1,000,000 lines (it was reached at about 6 MiB). Files of about 15.5–15.9 MiB now parse with coverage confirmed (pnpm about 3 seconds, Yarn Berry about 3 seconds, Bun 0.3 seconds)
- Coverage checks and relation analysis keep separate shared 2,000,000-operation budgets per format, so exceeding the relation budget does not change confirmed coverage. In uv, a dependency declared by several workspace members is traversed once
- New runtime dependencies: `jsonc-parser` (Bun) and `smol-toml` (uv, Poetry and PDM)
