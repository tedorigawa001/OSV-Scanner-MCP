# v0.12.1

- Fix recommendation checks incorrectly reporting a conflict when OSV returns a known vulnerability with no newer fixed version (`unfixed`). Such vulnerabilities remain visible in `per_cve_detail`, including their status at the recommended version.
- Continue withholding recommendations when OSV reports a vulnerability that the recommendation was intended to fix.
- Clarify that `candidate_check: "clean"` means no additional known vulnerabilities beyond those already shown in the scan, not that the recommended version is free of every vulnerability.
- Add regression coverage for primary IDs, aliases, and responses mixing known unfixed vulnerabilities with newly discovered vulnerabilities.

## Verification

- Automated tests (637), type check, and build
- Through MCP with the real OSV-Scanner binary: for PyPI `ecdsa==0.13`, v0.12.0 withheld the recommendation as a `conflict`; v0.12.1 recommends `0.19.2` (`candidate_check: "clean"`, `verification: "verified"`), and the unfixed PYSEC-2026-1325 is shown as `affected` at `0.19.2`
- With the check enabled, the `suggest_fix` responses for a project with npm, Go, PyPI, and Gradle lockfiles (16 packages) are identical to v0.12.0 except for `ecdsa`

npm publication is separate from this GitHub release.
