# v0.13.0

## Rust Upgrade Recommendations

- `suggest_fix` supports crates.io with SemVer and Cargo caret-compatible upgrade tiers, including breaking updates within 0.x.
- `unmaintained` and `notice` advisories, and `unsound` advisories without a newer fixed version, stay visible with `tier: "informational"` but are excluded from fix targets and unfixed counts. An `unsound` advisory with a newer fixed version is a fix target, because upgrading fixes it (it keeps `informational: "unsound"`). Packages with no fix target left return `verification: "informational_only"` without a recommendation.
- Candidate checks ignore known informational advisories and newly discovered unmaintained/notice records. Newly discovered unsound records remain fix targets.
- Cargo-specific update hints explain conditional `cargo update --precise`, manifest changes, parent requirements, pre-releases, build metadata, and patch/MSRV constraints. The server never runs Cargo.

## Cargo Dependency Relations

- Preserve the validated full Cargo.lock graph while scanning only crates.io packages.
- Resolve name-only, name/version, and exact source-qualified references; follow replacements and traverse git/alternate-registry dependencies without treating them as crates.io packages.
- Report direct/transitive relations, introduced_by, and uniquely mapped declaring Cargo.toml paths. Unmapped declaring crate names are available in declaring_crates.
- Ambiguous references remain unknown; graph traversal and manifest reads have explicit limits. Source URLs are not returned.

## Verification

- Automated tests (679), type check, and build. The tests use synthetic Cargo inputs, fake scanners, and stubbed OSV responses, and cover recommendation tiers, informational handling, graph resolution, ambiguity, cycles, limits, and update hints
- Through MCP with the real OSV-Scanner binary and the OSV check enabled, on a `Cargo.lock` with 38 vulnerable crates.io packages: 33 recommendations verified and `clean` (for example `tokio 1.8.0 → 1.38.2`, `lru 0.6.0 → 0.18.2`, `git2 0.13.0 → 0.21.0`, `borsh 0.9.0 → 1.0.0-alpha.1` with pre-release guidance, and `openssl-src 111.10.0+1.1.1g → 111.25.0`), 2 `informational_only` (unmaintained crates), and 3 withheld (no fixed version, or insufficient range data)
- Direct/transitive relations on real `Cargo.lock` files of 420 and 399 packages took 2–4 ms and left no crates.io package `unknown`
- `cargo update -p <crate>@<version> --precise <version>` behavior (within and outside requirements, duplicate versions, build metadata) was confirmed with Cargo 1.98 offline; this server never runs Cargo
